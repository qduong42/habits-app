# Tasks recur on reset-on-completion timestamps; habits stay on local dates

Habits are day-grained (one check-in per local date, streaks over dates), but recurring tasks use an `interval_hours` + `next_due timestamptz` model where the next due time resets from the last completion — the same model as Huy's 2026-05-13 household task tracker. Fixed-calendar recurrence ("every Monday") was considered and rejected: the canonical use cases (water plants, descale machine, every-12h chores) care about elapsed time since last done, not calendar position. Consequence: the app has two time grains on purpose — sub-daily tasks can appear, be completed, and reappear within a single local date, and task "doneness" is never unique per day the way habit check-ins are. Don't "fix" this by unifying the models.
